# 真实用户测试执行指南（T4 硬指标：≥20 名真实用户）

> 截止提醒：作品提交 **2026-11-30 24:00**。建议 **11-28 前**完成实测与数据回填，留 2 天缓冲。
> 诚信红线：本工具包产出的是**真实测试**流程与空表。工作区里的《用户测评-模拟数据20份.xlsx》是明确标注的模拟数据，只用于预演统计口径，**不得混入真实记录、不得作为证据提交**。

## 一、准备（0.5 天）
1. 后端部署到可访问地址（内网穿透见 `docs/内网穿透.md`），`/health` 确认索引块数正常。
2. 微信开发者工具上传体验版，生成体验版二维码（见 `docs/体验版发布与测试.md`）；把二维码发进招募群。
3. 打印或在线分发《用户体验问卷-每人一份.docx》（在线版可用问卷星/腾讯问卷按同口径建 5 题）。
4. 准备示例成绩数据口播稿：让测试者录 2–3 门课（如 高数 4 学分 86、英语 3 学分 91、程序设计 3 学分 78），避免每人乱录导致口径不齐。

## 二、招募与执行（1–2 天）
- 招募 20–30 人：本班 + 室友 + 社团，覆盖不同年级/专业（复用推广故事更好讲）。
- 每人流程：扫码进体验版 → 完成至少 3 项任务（①问制度要来源 ②算绩点 ③请假条导出；④拍通知可选）→ 填问卷 → 截 1–2 张使用截图发回。
- 现场/远程协助时只提示不代操作；「提示后完成」如实记，不要美化成「独立完成」。
- 失败也记录：API Key 不会配、拍照反光等正是迭代依据（PPT 已据此讲改进闭环）。

## 三、录入与汇总（0.5 天）
1. 打开《用户测试记录表-空白模板.xlsx》「测评明细」：每人一行，状态/评分/标签用下拉选，日期填真实日期。
2. 「汇总统计」页公式自动出完成率、四维均分、标签计数——无需手算。
3. 核对：登记人数 ≥20；完成率分母 = 登记人数；均分保留两位。

## 四、回填与留痕（提交前必做）
- [ ] 设计文档 `docs/需求分析与设计文档.docx` §2.3 实测登记表：逐项填写。
- [ ] 答辩 PPT 第 4 页「用户测试」：把示例数据（n=26 等）替换为真实 n 与真实比率/均分/反馈 Top3。
- [ ] 留痕归档到 `docs/用户测试工具包/实测留痕/`：问卷原始导出、记录表填写版、使用截图、二维码分发记录（群接龙/报名名单）。
- [ ] 模拟数据文件移出提交包（或保留但文件名与内容均标明「模拟-仅流程预演」，且不出现在证据链中）。

## 五、答辩口径
- 评委问「测试怎么做的」：出示二维码分发记录 + 问卷原始表 + 截图，说明任务口径与失败案例的改进动作。
- 评委问「数据可信吗」：记录表逐人可溯（编号↔问卷↔截图），失败与提示后完成均如实计入。
