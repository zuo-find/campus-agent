## 二、20 名真实用户测试怎么组织（这条是硬指标，别拖到最后）

- **招募**：本班 + 室友 + 社团，20–30 人，覆盖不同年级/专业更能讲"复用推广"故事。
- **形式**：发小程序体验版二维码，给每人 3 个任务（① 问一个制度问题 ② 算一次绩点 ③ 记一条 ddl），再填一份 5 题问卷（易用性、回答准确度、是否愿意继续用、最想加的功能、1–5 分打分）。
- **留痕**：问卷结果、使用截图、评分均值，直接进需求文档和答辩 PPT —— 这是"需求真实性 25 + 落地价值"最硬的证据。
- **复用故事**：记录"换一个学院只需替换知识库文档"这一点，对应"复用推广价值 30"。

## 三、答辩加分点（复评 100 分）

- **现场演示**走通"问制度→自动调工具→给来源"三段，体现 Agent 自主决策。
- **可解释性**：每个回答都有「来源：xxx」标注，评委问"会不会编"时直接展示 RAG 溯源。
- **创作过程核验**：出示 git 提交历史 + 工具单元测试，证明非 AI 一键生成。
- **分工清晰**：团队协作 30 分，PPT 里放清楚每人负责模块。
