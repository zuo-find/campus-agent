校园助手

v1.0.0
这是什么
「校园助手」是一个微信小程序。它不是把大模型套个聊天框——你问一句话，系统会先判断该由哪个专职智能体处理，再带着对应的资料和工具去回答。
比如问「奖学金怎么评」走校园问答，说「帮我写一份请假条」走材料撰写，问「比赛什么时候截止」走日程提醒，拍一道题走刷题陪练。回答末尾会标出依据来自哪份文件。
② 它想解决的问题
它想解决的问题
校园信息散、找不到学籍规定、重修办法、比赛通知散在官网各处，需要时翻半天。系统把学校公开发布的文件收进知识库，问一句就能答，并指出来源。
重复劳动多请假条、实训申请、活动策划这类材料格式固定却要反复写。系统按模板生成初稿，在线改字段，直接导出 Word。
信息要自己算绩点、剩余学分、距离报名截止还有几天，这些都要自己翻表格算。系统把时间点整理成带倒计时的待办，把成绩直接算成绩点和等级分布。

④ 怎么实现的 + 技术亮点
怎么实现的
小程序端微信小程序原生开发（WXML / WXSS / JS）。成绩、发布记录等个人数据只存本机，不上传服务器。
服务层FastAPI 提供服务。负责意图路由、知识库检索、工具执行、多模态调度与网页抽取。
模型层统一走 OpenAI 兼容接口，内置 9 家国内大模型厂商可选，用户可填自己的 API Key；识图单独配多模态模型。
几个值得说的点
1
多智能体路由，而非单一大模型用户的问题先经过一次轻量路由，判断归哪个智能体，再用该智能体的系统提示词与工具子集执行。回答里会显示「哪个智能体在应答」。
2
知识库检索做了工程细节按中文小标题切块而不是按固定字数硬切，避免把一节内容截断；检索时用原句加关键词多路召回；问题涉及时间时，含具体日期的片段会加权。
3
回答可溯源每条制度类回答都标注依据的文件名，知识库里没有的会明说「资料里没找到」，不编造。这一点在答辩现场可以直接验证。

说明
数据来源校园制度类内容取自学校公开发布的文件；用户上传的文件由用户本人提供，仅用于当次回答。
个人数据成绩、待办、发布记录只保存在用户手机本地，后端不存储；大模型 API Key 同样只存本地，随请求转发，服务端不落库。
AI 生成内容问答与材料初稿由大模型生成，可能不准确。制度类内容请以学校正式文件为准；材料生成后请自行核对修改再提交。
开发过程开发中使用了 AI 辅助编码，所用工具、用途与人工再创作情况另见随作品提交的《AI 工具使用声明》。
